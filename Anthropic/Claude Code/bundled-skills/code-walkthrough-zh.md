## 目标

为上方的目标生成一个**交互式解释 artifact**——一个新人可以从头到尾阅读以理解此代码做什么、各部分如何配合、以及为什么这样构建的自包含 HTML 页面。将写作定位在"像我刚来这里一样解释"：假设读者是有能力但从未看过此代码库的工程师。

## 先探索

阅读目标及其直接依赖（调用者、被调用者、它提及的类型、测试它的测试）。在写 artifact 之前构建心理模型。artifact 只和你的理解一样好。

## artifact 的结构

编写 HTML 文件并用 Artifact 工具发布。先加载 `artifact-design` 技能并给页面一个实用的处理——这是一个文档，不是落地页。

页面应按此顺序包含：

1. **一段摘要**——目标用途是什么，用通俗语言。
2. **地图**——主要部分及其连接方式的简短列表或简单图表。对于单个文件，这是关键函数/类型；对于目录是文件；对于 PR 是 before→after。
3. **演练部分**——地图中每个部分一个 `<details>` 块。每个内部：
   - 用通俗语言解释此部分做什么。
   - **带注释的代码片段**：真实代码（修剪到相关行）并附带对非显而易见部分的行内解释。
   - **"为什么这很重要"标注**——如果此部分不存在或工作方式不同，什么会损坏或变差。
4. **开放问题**——你无法从代码中确定但维护者会知道的任何东西。诚实的"我不知道"胜过猜测。

## 保持诚实

解释代码*实际做什么*（追踪它），而不是其名称暗示它做什么。当某部分确实简单时，简短说明并继续——不要填充。
