# 智能体设计模式

本文件涵盖在 Claude API 上构建智能体的决策启发式方法：该使用哪些原语、如何设计工具接口、以及如何在长时间运行中管理上下文和成本。关于各工具的机制和代码示例，请参见 `tool-use-concepts.md` 和语言特定目录。

---

## 模型参数

| 参数 | 何时使用 | 预期效果 |
| --- | --- | --- |
| **自适应思考**（`thinking: {type: "adaptive"}`） | 当你希望 Claude 控制何时思考及思考多少时。 | Claude 按请求决定思考深度，并在工具调用之间自动穿插思考。无需调整 token 预算。 |
| **努力程度**（`output_config: {effort: ...}`） | 当你需要调整彻底性与 token 效率之间的权衡时。 | 更低努力 → 更少且更集中的工具调用、更少的前言、更简洁的确认。`medium` 通常是良好的平衡。当正确性比成本更重要时使用 `max`。 |

模型支持和参数详情请参见 `SKILL.md` §思考与努力程度。

## 设计你的工具接口

### Bash 与专用工具

Claude 不知道你的应用安全边界、审批策略或 UX 界面。Claude 发出工具调用，你的 harness 处理它们。这些工具调用的形态决定了 harness 能做什么。

**bash 工具**赋予 Claude 广泛的程序化能力，它可以执行几乎任何操作。但它只给 harness 一个不透明的命令字符串，每个操作的形态都相同。将一个操作提升为**专用工具**则给 harness 一个特定于操作的钩子，带有类型化参数，可以拦截、门控、渲染或审计。

**何时将操作提升为专用工具：**

- **安全边界。** 需要门控的操作是天然的候选。可逆性是一个有用的判据：难以逆转的操作（外部 API 调用、发送消息、删除数据）可以在用户确认后门控。`send_email` 工具容易门控；`bash -c "curl -X POST ..."` 则不行。
- **过期检查。** 专用的 `edit` 工具可以在文件自 Claude 上次读取后已变更时拒绝写入。Bash 无法强制执行该不变量。
- **渲染。** 某些操作受益于自定义 UI。Claude Code 将提问提升为工具，使其可以渲染为模态框、展示选项，并阻塞智能体循环直到获得回答。
- **调度。** `glob` 和 `grep` 等只读工具可以标记为并行安全。当相同操作通过 bash 运行时，harness 无法区分并行安全的 `grep` 和并行不安全的 `git push`，因此必须串行化。

**经验法则：** 先用 bash 获取广度。当你需要门控、渲染、审计或并行化某个操作时，再提升为专用工具。

## Anthropic 提供的工具

| 工具 | 执行侧 | 何时使用 | 预期效果 |
| --- | --- | --- | --- |
| **Bash** | 客户端 | Claude 需要执行 shell 命令时。 | Claude 发出命令，你的 harness 执行。提供参考实现。 |
| **文本编辑器** | 客户端 | Claude 需要读取或编辑文件时。 | Claude 通过你的实现查看、创建和编辑文件。提供参考实现。 |
| **计算机使用** | 客户端或服务端 | Claude 需要与 GUI、Web 应用或视觉界面交互时。 | Claude 截屏并发出鼠标/键盘命令。可自托管（你运行环境）或由 Anthropic 托管。 |
| **代码执行** | 服务端 | Claude 需要在你不想管理的沙箱中运行代码时。 | Anthropic 托管的容器，内置文件和 bash 子工具。无客户端执行。 |
| **Web 搜索 / 获取** | 服务端 | Claude 需要训练截止日期之后的信息（新闻、时事、最新文档）或特定 URL 的内容时。 | Claude 发出查询或 URL，Anthropic 执行并返回带引用的结果。 |
| **记忆** | 客户端 | Claude 需要跨会话保存上下文时。 | Claude 读写 `/memories` 目录。你实现存储后端。 |

**客户端工具**由 Anthropic 定义（名称、schema、Claude 的使用模式），但由你的 harness 执行。Anthropic 提供参考实现。**服务端工具**完全在 Anthropic 基础设施上运行，在 `tools` 中声明即可，Claude 处理其余部分。

## 组合工具调用：程序化工具调用

标准工具使用中，每次工具调用都是一次往返：Claude 调用工具，结果进入 Claude 的上下文，Claude 对其推理，然后调用下一个工具。三个顺序操作（读取档案 → 查询订单 → 检查库存）意味着三次往返。每次都增加延迟和 token，而大多数中间数据再也不需要。

**程序化工具调用（PTC）**让 Claude 将这些调用组合成脚本。脚本在代码执行容器中运行。当脚本调用工具时，容器暂停，调用被执行（客户端或服务端），结果返回给运行中的代码，而非 Claude 的上下文。脚本用正常控制流（循环、过滤、分支）处理结果。只有脚本的最终输出返回给 Claude。

| 何时使用 | 预期效果 |
| --- | --- |
| 多个顺序工具调用，或希望在大型中间结果进入上下文窗口前过滤它们。 | Claude 编写以函数方式调用工具的代码。在代码执行容器中运行。token 成本随最终输出扩展，而非中间结果。 |

## 扩展工具和指令集

| 特性 | 何时使用 | 预期效果 |
| --- | --- | --- |
| **工具搜索** | 有很多工具可用，但每次请求只有少数相关。不想预先将所有 schema 放入上下文。 | Claude 搜索工具集并仅加载相关 schema。工具定义是追加的，而非替换的，保留缓存（见下方缓存）。 |
| **技能** | Claude 应仅在相关时加载的特定任务指令。 | 每个技能是一个包含 `SKILL.md` 的文件夹。技能描述默认在上下文中；当任务需要时 Claude 读取完整文件。 |

两种模式都保持固定上下文小，按需加载细节。

## 长时间运行的智能体：管理上下文

| 模式 | 何时使用 | 预期效果 |
| --- | --- | --- |
| **上下文编辑** | 上下文在多轮后变得陈旧（旧工具结果、已完成的思考）。 | 工具结果和思考块根据可配置阈值被清除。保持记录精简，不做摘要。 |
| **压缩** | 对话可能达到或超过上下文窗口限制。 | 早期上下文在服务端被摘要为压缩块。关键的 `response.content` 处理请参见 `SKILL.md` §压缩。 |
| **记忆** | 状态必须跨会话持久化（不仅仅在一次对话内）。 | Claude 读写记忆目录中的文件。在进程重启后存活。 |

**如何选择：** 上下文编辑和压缩在会话内运作，编辑修剪陈旧的轮次，压缩在接近限制时做摘要。记忆用于跨会话持久化。许多长时间运行的智能体三者并用。

## 智能体的缓存

**先阅读 `prompt-caching.md`。** 它涵盖了前缀匹配不变量、断点放置、静默失效审计，以及为何在会话中途更改工具或模型会破坏缓存。本节仅覆盖这些约束下针对智能体的变通方法。

| 约束（来自 `prompt-caching.md`） | 智能体特定变通方法 |
| --- | --- |
| 在会话中途编辑系统提示词会使缓存失效。 | 改为向 `messages[]` 追加一条 `{"role": "system", ...}` 消息（无需 beta 请求头；在支持的模型上，参见 `prompt-caching.md` § 会话中途系统消息）。缓存前缀保持完整，模型将其视为操作者权限指令而非用户文本。在不支持的模型上，回退为用户轮次中的 `<system-reminder>` 文本块。 |
| 在会话中途切换模型会使缓存失效。 | 为子任务用更便宜的模型派生一个**子智能体**，主循环保持在一个模型上。 |
| 在会话中途添加/移除工具会使缓存失效。 | 使用**工具搜索**进行动态发现，它追加工具 schema 而非替换，因此现有前缀得以保留。 |

多轮断点放置，使用顶层自动缓存，参见 `prompt-caching.md` §放置模式。
