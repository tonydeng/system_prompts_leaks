长篇文档布局：暖色纸张背景上的衬线正文，配有报头、目录、散文章节和可选附录。适合打印。

## 如何使用

1. 从此技能的基础目录（如上所示）读取 `template.html`。
2. 将其复制为起点。用真实内容替换每个 `<!-- SLOT: ... -->` 标记，每个 slot 内的注释描述了应放入的内容。每个 slot 在注释后还带有占位文本（示例标题、标题行、句子、要点、目录条目）；也需替换这些文本，仅删除注释标记会留下占位文本出现在已发布的页面中。
3. 自检填充后的 HTML：没有遗留的 `SLOT` 标记，没有遗留的占位文本，且每个目录（TOC）条目都指向实际存在的 section id。
4. 发布前对样式和内容进行一轮跟进审阅。模板提供的是默认结构和样式，并非必须遵循：精炼文字，并根据本文档的需要调整样式，重新调整 `--cds-*` 令牌值（在声明它们的每个作用域中，包括浅色 `:root` 块、两个深色作用域和 `@media print` 块，否则值会在深色模式或打印时回弹），重新设计组件样式，或在内容需要时重组结构（保持文本对比度可访问，且对于包含三个或更多章节的报告保留 TOC）。
5. 使用 `Artifact` 工具发布填充后的 HTML。

**仅限创建。** 编辑现有报告 artifact 时，直接使用其当前 HTML，不要重新读取或重新应用此模板。

## Slots

| Slot | 填入内容 |
| --- | --- |
| `TITLE` | 文档的标题主张或主题。 |
| `SUBTITLE` | 一句话陈述关键发现或范围。 |
| `KEY_TAKEAWAYS` | 可选，3-5 个要点，**每条一行**：一个带有数字或具体内容的单从句，不要子从句或第二句。这是 SUBTITLE 单句之下的要点层级；不要重述它，也不要把要点扩充成段落。短文档可省略整个 `<aside class="takeaways">`。 |
| `TOC_ITEMS` | 每个 `<h2>` 对应一个 `<li><a href="#id">章节标题</a></li>`。在写完 SECTIONS **之后**，根据你实际写的标题来填写。模板中的小脚本会从渲染的章节重建列表，因此锚点在屏幕上会自动修复，静态列表是脚本不运行时的回退。 |
| `SECTIONS` | 每个主要主题对应一个 `<section id="...">`，各含一个 `<h2>` 和正文散文。用 `<h3>` 表示子章节，`<table>` 表示结构化数据，`<pre>` 表示代码，`<blockquote>` 表示标注，`<figure>` + `<figcaption>` 表示图表。每个章节以其结论开头。 |
| `APPENDIX` | 可选，会打断主线流程的辅助材料。不需要时省略整个 `<section class="appendix">`。 |

模板还有一个用于报头眉注（文档类型/日期）的小型内联 slot，就地标注。

## 内容

尊重读者的注意力，这是报告消耗的最稀缺资源：

- 以最重要的内容开头。副标题承载标题级发现，要点承载最关键的细节，每个章节以其结论开始；细节、方法和原始数据放在后面，或放入附录。
- 写得清晰简洁：用平实的语言、短句，每个专业术语首次使用时定义，不使用未解释的缩写。删掉任何不改变读者认知或决策的内容。
- 说明证据是什么以及每个主张的确信度：区分测量的内容、推断的内容和推测的内容，而不是以同样的语气呈现这三者。
- 当图表比文字更能表达要点时使用图表，如趋势、对比、结构。将图形绘制为 `<figure>` 内的自包含内联 SVG，绝不使用外部图像（artifact 必须在无网络访问时也能渲染），并为每个图形添加 `<figcaption>` 说明读者应从中获取的信息。

## 注意事项

- 模板是一个** body 片段**，没有 `<!DOCTYPE>`/`<html>`/`<head>`/`<body>` 包裹。Artifact 工具在发布时会添加自己的骨架。
- 用完整句子写真正的散文。布局针对约 65 字符的行宽进行了调优。
- 样式默认值以内联 `--cds-*` 自定义属性提供（自包含，artifact 在无网络访问时也能渲染），在浅色 `:root` 块中声明，并在两个深色作用域和 `@media print` 块中重新声明。它们是默认值而非强制值：在跟进审阅中可以在声明它们的每个作用域中重新调整，或完全重新设计样式。
