交互式表格布局：一个筛选输入框、一个紧凑的可排序表格（点击列标题排序）和一个行计数。数据以 JSON 数组形式嵌入；内置渲染器负责绘制和重新排序。

## 如何使用

1. 从此技能的基础目录（如上所示）读取 `template.html`。
2. 将其复制为起点。用真实内容替换每个 `<!-- SLOT: ... -->` 标记，每个 slot 内的注释描述了应放入的内容。每个 slot 在注释后还带有占位文本（示例标题、示例行、示例值）；也需替换这些文本，仅删除注释标记会留下占位文本出现在已发布的页面中。
3. 发布前自检填充后的 HTML：没有遗留的 `SLOT` 标记，没有遗留的占位文本。
4. 使用 `Artifact` 工具发布填充后的 HTML。

**仅限创建。** 编辑现有数据表 artifact 时，直接使用其当前 HTML，不要重新读取或重新应用此模板。

## Slots

| Slot | 填入内容 |
| --- | --- |
| `TITLE` | 纯文本页面标题，例如"产品目录"。出现**两次**，顶部附近的 `<title>` 元素（用于命名浏览器标签页和 artifact 本身）以及页头中可见的 `<h1>`。两者都需填写。 |
| `COLUMNS` | 列定义的 JSON 数组：`{key, label, type}`。`type` 为 `"text"` 或 `"num"`（右对齐，数字排序）。 |
| `ROWS` | 行对象的 JSON 数组，每个对象以列键为键。嵌入完整数据集，渲染器负责滚动（大小上限见数据规则）。 |
| `FOOTER_NOTE` | 数据来源和生成时间戳。 |

模板还有一个用于页头范围文本的小型内联 slot，就地标注。

## 数据规则

- `"num"` 列中的值必须是 JSON 数字，而非字符串，`1234.5` 而非 `"1,234.50"` 或 `"$1,234.50"`。去除货币符号和千位分隔符，将单位放在列标签中（例如"金额（美元）"）。`"num"` 列中的非数字值（如 `"$1,234.50"` 的字符串或布尔值）原样显示但跳过数字格式化并排到末尾。
- 缺失值为 `null`（或省略该键），绝不用 `0`、`"N/A"` 或 `"-"`。空字符串和纯空白字符串也算缺失。渲染器将缺失单元格显示为空白并排在最后排序。
- 日期放入 `"text"` 列，格式化为 ISO-8601（`2026-07-08`），这样字母排序也是时间排序。人类风格日期（"Jul 8, 2026"）排序会出错。
- 两个 JSON 块必须是严格 JSON：双引号、无尾随逗号、无注释、无 `NaN`/`Infinity`。
- 在 JSON 字符串值中，将 `</` 转义为 `<\/`，将 `<!--` 转义为 `<\u0021--`（两者都是有效的 JSON 并会解析回原始文本）。未转义时，`</script` 会提前终止 script 块，导致表格损坏并让值的其余部分渲染为活动的 HTML，而 `<!--` 会在 script 数据中打开类似 HTML 注释的状态，产生类似的破坏效果。
- 数字最多显示 6 位小数。预先将值舍入到值得显示的精度，混合精度会使右对齐列参差不齐。
- 嵌入完整数据集，最多几千行。超过此数量，将数据子集化或聚合为用户实际会浏览的内容，并在 `FOOTER_NOTE` 中说明删减了什么。

## 在此基础上重新设计样式

模板的价值在于其可用的机制：布局、排序、筛选。内置样式是简洁的默认值（每个绘画令牌都有深色对应项），而非最终外观：当用户的请求或主题暗示不同的感觉时，在其基础上重新设计样式。

- 可安全重新设计样式的部分：整个 `<style>` 块，颜色、排版、间距、条纹、圆角。更改调色板令牌时，在声明它的所有四个作用域中更改，包括浅色 `:root` 块、`@media (prefers-color-scheme: dark)` 块、`:root[data-theme="dark"]` 块和 `@media print` 块（打印始终为浅色，此处遗漏的令牌会在纸张上回退到内置调色板），这样重新设计的表格会跟随操作系统的深色设置、查看器的主题切换和打印。仅在 `:root` 中更改的值会在深色模式和打印时回弹到内置调色板。
- 保持不变的部分：主题结构本身（所有四个作用域，包括 media 块上的 `:where()` 保护、`color-scheme` 固定和 `@media print` 重新固定块）、表格标记结构、`<script>` 块以及脚本读取的 id 和 class，包括 `dt`、`dt-filter`、`dt-count`、`arrow`、`sorted`、`num`、`empty`。重命名或移除这些会破坏排序、筛选或主题功能。

## 注意事项

- 模板是一个** body 片段**，没有 `<!DOCTYPE>`/`<html>`/`<head>`/`<body>` 包裹。Artifact 工具在发布时会添加自己的骨架。
- 数据放在两个 JSON `<script>` 块中，而非字面的 `<tr>` 标记，渲染器拥有行输出的控制权以确保排序和筛选正常工作。
- 筛选输入框在所有文本列中匹配子字符串，数字列不参与文本筛选。无匹配结果的筛选会显示内置的"无匹配行"消息，不要添加自己的。
- 如果不同的色调效果更好，可在声明 `--accent` 的每个作用域中（参见"在此基础上重新设计样式"）将其调整为适合主题的色调。
