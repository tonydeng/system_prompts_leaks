将 markdown 计划转为已发布的 Artifact，采用标准计划处理。所有计划 artifact 共享一个受祝福的模板，使它们读起来像一家人：相同的字体系统、相同的调色板、相同的节奏，在浅色和深色模式下都是如此。

在 plan mode 中批准的计划已经可以从批准对话框的发布选项（或 `/plan share`）发布——该内置路径机械地填充此同一模板，仅在用户选择时运行。当人类要求你手动创建计划 artifact、重新发布编辑过的计划、或定制内置发布产生的内容时，使用此技能。

## 流程

始终从模板开始。永不要从头写 HTML 外壳——外壳就是一致性。

1. **复制模板。** 将此技能基础目录（上方列出）中的 `templates/artifact-plan.html` 复制到工作 `plan.html`，放在你的系统提示词中列出的草稿目录（如有），否则放在其他临时文件旁边。

2. **编辑副本——仅内容。**
   - 删除开头的 HTML 注释头。
   - 用计划的标题填充 `{{TITLE}}` 和 `{{TAB_TITLE}}`，用简短上下文标签如 `Plan · <project name>` 填充 `{{EYEBROW}}`，用一句话导语填充 `{{SUMMARY}}`。
   - 将每个 `<!-- SLOT: … -->` 注释替换为该部分的 HTML 内容。转换计划的 markdown；`<h2>` 标题已提供。添加或删除整个 `<section>` 块使文档匹配计划的实际结构——四个起始部分是建议，非要求。
   - 保持 `<style>` 块完整，包括深色模式 token 集——每个计划 artifact 都携带两套主题。保持 `<script>` 主题 shim 完整：它将查看器切换的 `data-theme` 标记镜像到 token 块的 `data-mode`，移除它会悄悄杀死页面的切换轴，而图表仍跟随它。仅当用户明确要求不同外观时扩展或重新样式化，并尽可能保持其变更加性。

3. **发布** 文件，使用 Artifact 工具。
