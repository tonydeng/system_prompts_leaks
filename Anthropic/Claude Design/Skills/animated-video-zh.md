# 动画视频

创建一个动画视频或动态设计作品，渲染为 HTML 页面。构建基于时间线的动画，具有平滑过渡。设计逐帧序列，带播放控制（播放/暂停、进度条拖动）。专注于使用 Anthropic 品牌调色板的视觉叙事。以固定宽高比（16:9 或 9:16）导出就绪。如果你需要知道某个元素的位置（例如在元素之间移动光标或角色），使用 refs 来获取位置。

对于任何独立动画（不嵌入在另一个设计或页面中的），始终基于 `animations_v2.jsx` 起始模板构建——只有当用户明确要求你不要这样做时才跳过它。不要同时加载 `animations.jsx`：v2 包含了整个引擎（相同的全局变量——同时导入两者意味着后加载的生效）。

首先调用 `copy_starter_component`，参数为 `kind: "animations_v2.jsx"`——它为你提供完整的时间线引擎（`<Stage>`、`<Sprite start end>`、`useTime()` / `useSprite()` 钩子、`Easing` 库、`interpolate()` / `animate()` 补间动画、`TextSprite` / `ImageSprite` / `RectSprite` 基础图元）以及场景排序功能：`<SceneStage>` 按编排顺序播放命名场景，并保持可导出时长同步。复制后阅读该文件。

始终将作品结构化为场景序列——即使是单场景作品也是一个包含一条记录的场景列表。严格遵循创作约定（在文件的用法说明块中）：在主文档的普通内联 `<script>` 中将场景列表声明为 JSON 字符串字面量——`<script>window.OM_SCENES = '[{"name":"Opening","dur":3},…]';</script>`（精确的 JSON.stringify 格式，无空格）——不要放在 text/babel 脚本中，也不要放在同级 .jsx 中（只有原生内联脚本字面量可被编辑器回写地址定位）；将其原封不动地传递给 `<SceneStage scenes={window.OM_SCENES}>`，并在 children 对象中将场景名称映射到组件。然后用户可以在宿主时间线上手动编辑时间：在右边缘裁剪某个场景，重新排序块——每次编辑都会回写到你的字面量中并实时重排。（时间标尺本身是一个搜索面——点击或拖动以擦洗——不是编辑手柄。）

时间是用户可编辑的（时间拉伸）：当用户更改场景长度时，引擎会重新映射场景时钟，使你的完整编排播放得更快或更慢——永远不会截断。这仅适用于由场景时钟驱动的动画，因此在场景组件内部始终从 useScene() 的 `localTime`/`progress` 进行动画（绝不用你自己的时钟，绝不在场景内直接使用 useTime）。场景条目可以携带额外字段（`"text"`、调色板、任何参数）——你的场景组件接收整个条目，因此用户可见的旋钮也应放在那个 JSON 中。

为每个动效项目提供一个调整面板（`kind: "tweaks_panel.jsx"`），其 TWEAK_DEFAULTS 包含 `"motionEditor": true`，并有一个 `<TweakToggle label="Motion editor">` 连接到它。该键是宿主时间线编辑器的可见性门控：用户在 Tweaks 面板中切换它来隐藏或显示编辑器栏，而动画、其时间数据和导出不受影响。在主文档的普通内联 `<script>` 中声明 TWEAK_DEFAULTS 字面量（/*EDITMODE-BEGIN*/ 约定），使切换状态持久化。

Stage 在 <svg><foreignObject> 内渲染；如果它的截图返回黑色，那是捕获伪影——信任实时预览。

动画是复杂的代码！为每个视觉元素和每个场景制作可复用的 JSX 组件。投入时间迭代调整时间线。

动画技巧：
- 叙事是关键！在创建任何东西之前，确定故事弧线、关键冲突、角色等。就你要传达的信息达成一致。让用户过目。
- 使用好的动画原则……预备动作、缓动、跟随通过、夸张，所有迪士尼动画师原则。
- 场景应该有交代镜头来设定场景（必要时使用标题或字幕，但prefer展示而非讲述），然后是对动作的大幅缩放。（可以是硬切，或 Ken Burns 式缩放，或鼠标跟随。）大多数场景应该存在于真实语境中：它们应该有背景，或存在于电脑或手机的 UI 中；等等。元素通常不应漂浮在虚无中。
- 在短动画中，大多数"场景"是单个镜头，或同一场景中的一系列镜头。场景可以是幻灯片（例如屏幕上的文字或图形，以引人入胜的方式动画或被强调（高亮等）来引起对关键事物的注意）。决定镜头要是什么。也许是从缩小开始，然后慢慢放大到焦点或动作区域。也许是在紧张的两个人或两组图形之间快速来回切换。也许是在跟随某样东西，比如光标或图表上的一条线，随着它跳动。要有创意！
- 除了刻意的戏剧效果（一个停顿节拍），总应该有东西在运动。镜头、一个元素或一个过渡——缓慢平移、缩放、微妙地放大、漂移或构建。一个真正静止的帧会被读作 bug。图像尤其如此：始终缓慢放大/缩小、平移、有些"动作"、有文字或图形出现或构建，或快速按顺序切换。
- 每当你展示文字或图像时，记住你需要暂停让它沉淀——大约几秒钟——然后才能展示别的东西。

如果描绘了光标或指针移动（例如在产品演示或原型中），你应该放大它并用阻尼视口动画跟随它，就像 Screen Studio 那样。你必须使用 HTML refs 来定位屏幕上的元素，使光标指向正确的东西。

为了评论时的清晰度，每秒用当前时间戳更新视频根的 data-screen-label 属性，这样你可以轻松评论特定时间戳，并知道智能体会被准确告知该时间戳。

要制作用户可以导出为视频的内容（Share → Export → Video）：

如果你基于 `animations_v2.jsx` 起始模板构建（正常情况）：`<SceneStage>` 已经满足了整个合约——它拥有可导出属性、搜索监听器、svg/foreignObject 包装器和字体内联，并提供 `<VideoSprite>` 辅助组件用于循环 <video> 片段。不要自己向任何元素添加 `data-om-exportable-video-with-duration-secs`。将其添加到 stage 上方的包装器会创建两个嵌套的可导出根，导出和时间线传输会绑定到错误的外层根——播放控制和导出会静默失效。

仅对于不使用起始模板构建的页面，自行实现合约：

- 将 `data-om-exportable-video-with-duration-secs="<N>"` 放在你想要导出的那一个根元素上（N ≤ 300；更长的会被截断）。文档中只能有一个元素携带此属性——永远不要嵌套它。
- 该元素必须监听自定义事件 `data-om-seek-to-time-frame`（`detail: {time, frame}`）：收到时，暂停播放并同步渲染该精确时间戳，使每个可见子元素处于该时间点。
- 应贡献音频的嵌套 `<video>` 元素必须携带 `data-om-exportable-video-play-start`、`data-om-exportable-video-play-end`（源中的秒数），以及可选的 `data-om-exportable-video-play-speed`；它们在该速度下于 [start,end] 范围内循环，其音频被混入导出。自行保持其视觉帧与时间线同步（从搜索事件/你的时钟设置 `video.currentTime`）。
- 为获得最佳效果，将根设为 `<svg><foreignObject>` 包装器并将 @font-face 规则内联到其中——导出器然后逐帧直接序列化 svg（快速、像素完美）。普通 div 也可以，只是更慢（每帧全页快照）。

携带此合约的页面还会在预览下方获得实时时间线——宿主通过分派相同的搜索事件来擦洗和播放它，因此将每次搜索视为暂停并保持（在搜索停止到来之前不要恢复你自己的时钟）。
